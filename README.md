# 즐거움 Live

Delightful Experiences Education · 2026 파닉스 설명회

학부모가 서로 다른 두 QR로 각각 참여하는 익명 투표입니다. 이름 입력이나 앱 설치 없이 각 질문에서 3개를 선택합니다.

## 사용 방법

1. 발표 컴퓨터에서 `/display`를 엽니다. 첫 화면에는 **오늘밤 저메추**의 순위와 오른쪽 전용 QR이 나옵니다.
2. 학부모는 그 QR을 찍고 메뉴 3개를 선택한 다음 **투표 제출하기**를 누릅니다. 순위와 막대가 자동으로 움직입니다.
3. 발표 화면을 **아래로 스크롤**하면 **학원 선택 기준**과 오른쪽의 다른 QR이 나옵니다.
4. 두 번째 QR을 찍고 기준 3개를 별도로 제출합니다. 첫 번째 투표 참여 여부와 관계없이 참여할 수 있습니다.
5. 진행자는 `/admin`에서 비밀번호를 입력합니다. 각 질문을 따로 마감·재개하거나 새 회차로 시작할 수 있으며, 결과를 CSV로 저장할 수 있습니다.

QR은 질문과 현재 회차를 포함합니다. 새 회차를 시작하면 해당 질문의 QR만 바뀝니다. 이전 기록은 보관됩니다. 같은 브라우저에서 같은 질문·회차로 제출한 답은 한 번만 집계됩니다.

## 서버 설정과 배포

기존 Vercel 프로젝트의 Production 환경 변수에 아래 값을 저장합니다. 실제 값은 소스나 공개 파일에 넣지 않습니다.

| 환경 변수 | 용도 |
| --- | --- |
| `DATABASE_URL` | 영구 Neon 데이터베이스 연결 |
| `ADMIN_PASSWORD` | 진행자 비밀번호, 4자 이상 |
| `VOTER_SECRET` | 익명 브라우저 식별자 해시를 만드는 고정 비밀 값, 16자 이상 |

Node.js 24, 빌드 명령 `npm run build`, 출력 폴더 `dist`를 사용합니다. 이미 생성된 사전 빌드 배포를 대시보드에서 Redeploy하는 대신, 새 소스로 배포해야 합니다.

```bash
npm ci
npx vercel login
npx vercel link --project temporary-zippy-beryl-0k4nbtk --scope d1s
npx vercel --prod
```

기존 데이터베이스의 옛 기록은 삭제하지 않습니다. 이 버전은 질문별 `live_rounds`, `live_events`, `live_ballots` 테이블을 사용합니다. 이전 버전의 실제 참여 기록이 있다면 새 버전을 공개하기 전에 활성 회차의 각 답변을 질문별로 이관합니다.

## 로컬 연습

```bash
npm ci
LOCAL_PREVIEW=1 npm run dev
```

`http://localhost:4173`에서 실행됩니다. 로컬 연습은 운영 DB와 분리되어 `.local/live.sqlite`에 저장되고 진행자 비밀번호는 `1234`입니다. `LOCAL_PREVIEW=1`이 없으면 `.env.local`의 서버 설정을 사용합니다. 휴대폰 참여에는 실제 배포 주소가 필요합니다.

## 집계

결과 화면은 2초마다 최신 집계를 가져옵니다. 동점은 공동 순위입니다. 선택 비율의 분모는 각 질문의 참여 인원이며, 한 명이 3개를 선택하므로 모든 항목의 합계는 300%입니다. 이름·전화번호·이메일·IP는 투표 DB에 저장하지 않습니다.

비밀번호 변경과 익명 식별은 분리되어 있습니다. `ADMIN_PASSWORD`를 바꾸더라도 `VOTER_SECRET`을 유지하면 같은 브라우저의 제출 여부가 그대로 확인됩니다.

`npm test`는 두 투표의 독립성, 동시 중복 재시도, 집계, 잘못된 선택 거부, 질문별 마감·새 회차, 이전 QR 차단, 4자리 관리자 인증, 비밀번호 변경 후 식별 유지를 검증합니다.
